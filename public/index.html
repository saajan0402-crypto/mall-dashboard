過去データの取り込み案件ごとに一度だけ

楽天

楽天は、ふだんは直近60日を毎日取り直しています。接続したばかりの案件は、一度これで過去の月を埋めてください。 30日ずつさかのぼり、5分ごとのバッチが裏で進めます（画面を閉じても大丈夫です）。同じ期間を何度取り込んでも二重にはなりません。

ヘッダーで選んだ案件が対象です。 画面を閉じても構いません。5分ごとのバッチが裏で進め続けます。 開いたままにしておくと、そのぶん早く終わります。

3段階で進みます。 ①売上（注文API）は速く、365日でも20分ほどで終わります。 ②セッション数はAmazonのレポートから取りますが、依頼と取得がそれぞれ1分に1回しか呼べないため 1日あたり約2分、30日ぶんで1時間かかります。365日なら半日ほど、730日なら丸1日ほど裏で動き続けます。 ③入金明細で手数料の実額と返品額が入ります。

②を外すと速く終わりますが、過去分のCVRが出せません。 広告の評価に使う数字なので、入れておくことをおすすめします。 直近7日はふだんの処理が持っているので、ここでは8日前より古い分だけを取りに行きます。

商品別の売上

請求明細の取り込み実額に置き換えます

楽天は RMS の「請求・支払明細」の CSV（ファイル名が …_Shop_Billpay.csv）をそのまま入れてください。 1つの明細に対象月の違う項目が混ざっているので、行ごとの精算対象期間で月に振り分けます（「対象月」の指定は使いません）。 楽天ペイの入金の行は費用ではないので取り込まず、RPP の広告掲載料は広告費として別に数えているので手数料には入れません。 請求額は税抜で載っているので、税率をかけて税込にそろえます。

その月のシステム利用料と楽天ペイ利用料の両方がそろうと、手数料が概算から実額に切り替わります（片方だけだと少なく見えるため）。 楽天ペイ利用料は1か月早い明細に載るので、続けて2本入れるとそろいます。同じ明細を何度入れても二重にはなりません。 ほかの書式や手入力のときは、ここの「対象月」の月として入ります。

請求明細は店舗単位で、商品ごとの内訳はありません。 店舗の合計は実額になりますが、商品別の手数料は売上で按分した値になります。 月全体の粗利は正確に、商品別は目安、という使い分けになります。

Amazon広告の自動取り込みAds API／毎朝6時に直近14日を取り直す

取り込むのは SP（キャンペーン別・商品別・キーワード別・検索用語）と SB（キャンペーン別・検索用語）の6種類です。 レポートはAmazon側で出来上がるまで数分〜数十分かかります。押したあと画面を閉じても、5分ごとのバッチが裏で取りに行きます。

広告経由の売上はクリックから7日（SP）／14日（SB）の間あとから増えるので、毎朝14日ぶんを取り直して最新の値に置き換えます。 Amazonが過去のデータを持っているのは SP が95日、SB が60日までです。それより前はCSVで入れたものが残ります。

同じ日・同じ種類は、APIの値がCSVで入れた値を置き換えます。 APIでは「予算内に収まっていた時間」と「掲載枠別」は取れないので、必要なときだけCSVで補ってください。 配信の無かった日は行が無いため、下の取り込み状況では空白に見えます。

広告レポートの取り込み（CSV）楽天RPP／Amazonで API が取れない種類

広告の実績

ROASは売上の帰属期間が種類ごとに違います。 楽天RPPは30日（720時間）、Amazon SPは7日、SBは14日です。帰属期間が長いほど売上が多く数えられるので、 違う種類どうしのROASをそのまま比べないでください。表の「帰属」列で確認できます。

楽天の表示回数はインプレッションが返らないため、クリック数とCTRからの逆算です。 CTRが0.00と出る低い行は求められないので「—」になります。 検索用語のインプレッションシェアはAmazon上に30日しか残らないので、こまめに取り込むと履歴が貯まります。

新しいキーワードの候補まだ入札していない語／Amazon の推奨と、検索語レポートで売れた語

入札を追加したら「追加した」を押してください。追加済みに移り、ダッシュボードの「対応の記録」とレポートの「対応したこと」に載ります。関係ない語は「見送る」で候補から外せます（どちらも元に戻せます）。
Amazon：「検索語で売上あり」は、自動ターゲティングや部分一致で売れたのに、キーワードとしてはまだ入札していない語です（直近60日）。 楽天：楽天には検索語のレポートが無いので、Amazon で売れた語・Amazon の推奨のうち、楽天RPPでまだ入札していない語を出します（推奨入札は Amazon の値なので出しません）。
「Amazon の推奨」は、広告 API が自社 ASIN ごとに勧めるキーワードで、週に1回取り直します。推奨入札は太字が中央値、下が範囲です。気になる語は「監視する」で、競合と自社の順位を毎日記録できます。

  • 商品API 2.0 のうち有料なのは items.get と items.bulk.getです。 使うのは無料の items.search だけなので、有料の2つにはチェックを入れないでください
  • 楽天のライセンスキーは90日ごとに更新が必要。切れると全APIが一斉に401になります
  • 2025年6月に楽天の認証方式が変わり、licenseKey は「アプリ」単位で発行される形になりました。 serviceSecret と licenseKey は同じアプリの組み合わせである必要があります
  • 機能のチェックを変えたあと、ライセンスキーの再発行が必要な場合があります
  • 楽天のRPP広告にAPIはありません（楽天に確認済み）。広告データはCSV取り込みのままです
  • 設定が終わったら、下の該当案件で「APIを一通り試す」を押して全部通るか確認してください
