① 共有URLを貼る開くたびに最新の数字で作り直されます

URLを知っている人は、ログインなしでこの案件のレポートを読めます。 社外に貼らない・用が済んだら「無効にする」を押す、を徹底してください。読めるのはこのレポートだけで、 接続情報や他の画面・他の案件には届きません。

AIが「開けない」と言うとき（初回だけ必要な設定）

このアプリは Cloudflare Access で守られているので、そのままでは外のAIが読めません。 /share/ だけを Access の対象外にする設定が一度だけ必要です。

  1. Cloudflare Zero Trust → Access → Applications → Add an application → Self-hosted
  2. Application domain に、いまのアプリと同じドメインを入れ、Path に share と入れる
  3. Policy を1つ作り、Action を Bypass、Include を Everyone にして保存
  4. ここで発行したURLをシークレットウィンドウで開き、ログイン画面が出ずにレポートが表示されればOK

パスを指定したアプリはドメイン全体のアプリより優先されるので、/share/ 以外は今まで通りログインが必要なままです。 それでもAIが読めない場合は、下の②を使ってください。

残り日数は「販売可能な在庫 ÷ 直近28日の1日あたり販売数」です。納品中は含めていません。 販売実績のない商品は日数を出せないので「—」になります。 しきい値は商品マスタの「在庫アラート日数」、未設定なら会社共通の設定を使います。

「定期便の契約」は継続中の契約数、「30日の出荷見込み」はそのうち今後30日に実際に出荷される見込みの数量です。 顧客が配送間隔（1か月／2か月／3か月）を選べるので、契約数より少なくなります。判定に使うのは出荷見込みのほうです。

定期おトク便は確定した将来需要なので、販売ペースより優先して判定します。 今後30日の定期便が販売可能な在庫を上回っていたら、残り日数に余裕があっても「欠品間近」にします。 在庫切れで定期便を届けられなかった実績があれば「在庫切れ」扱いです。

広告レポートの取り込み楽天RPP・Amazon広告（CSV）

何ファイルでも一度に選べます。 楽天の商品別・キーワード別は1回の操作で1日分しか落とせないので、 何日分かためて落としてから、まとめて放り込んでください。 同じ日を入れ直しても二重にはなりません。

楽天：月ごと集計のファイルは取り込めません（日付が1日に定まらないため）。 RMSの「集計期間」で日ごと、または1日ぶんを選んで出してください。 キャンペーン別は日ごと集計で1か月まとめて落とせます。

Amazon：レポートの単位は「日別」、形式はCSVで出してください（Excelは読めません）。 対応しているのはキャンペーン・検索用語（SP／SB）・掲載枠・広告された商品の4種類です。 ファイルの中身を見て種類を自動で判定するので、ファイル名は何でも構いません。

広告の実績

ROASは売上の帰属期間が種類ごとに違います。 楽天RPPは30日（720時間）、Amazon SPは7日、SBは14日です。帰属期間が長いほど売上が多く数えられるので、 違う種類どうしのROASをそのまま比べないでください。表の「帰属」列で確認できます。

楽天の表示回数はインプレッションが返らないため、クリック数とCTRからの逆算です。 CTRが0.00と出る低い行は求められないので「—」になります。 検索用語のインプレッションシェアはAmazon上に30日しか残らないので、こまめに取り込むと履歴が貯まります。

つまずきやすいところ

  • 商品API 2.0 のうち有料なのは items.get と items.bulk.getです。 使うのは無料の items.search だけなので、有料の2つにはチェックを入れないでください
  • 楽天のライセンスキーは90日ごとに更新が必要。切れると全APIが一斉に401になります
  • 2025年6月に楽天の認証方式が変わり、licenseKey は「アプリ」単位で発行される形になりました。 serviceSecret と licenseKey は同じアプリの組み合わせである必要があります
  • 機能のチェックを変えたあと、ライセンスキーの再発行が必要な場合があります
  • 楽天のRPP広告にAPIはありません（楽天に確認済み）。広告データはCSV取り込みのままです
  • 設定が終わったら、下の該当案件で「APIを一通り試す」を押して全部通るか確認してください
